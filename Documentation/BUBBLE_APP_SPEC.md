# シャボン玉あそび Webアプリ仕様書

## 1. 目的

スマートフォンで遊ぶシャボン玉アプリ。

年齢や利用者の立場を限定しない。UIには特定の年齢層や立場を前提とした文言を配置しない。

ルール理解や正確な操作を求めず、触る・押し続ける・なぞることで、すぐに視覚的な反応が返ることを重視する。点数・勝敗・制限時間は設けない。

## 2. 要件の区分

### 確定した主要仕様

- 空いている場所を短くタップすると最小サイズのシャボン玉ができる。長押しすると膨らませられる。
- 長く押すほどシャボン玉が大きくなる。最大直径は画面横幅の約2/3とし、横画面では高さにも収まるよう制限する。
- なぞると、その方向へシャボン玉が流れる。
- シャボン玉をタップすると、大きく伸び縮みして揺れ、徐々に収まる。
- 割れるまでのタップ回数は、玉ごとに生成時に1〜6回から等確率で決める。途中で回数は変えず、設定からも変更しない。
- 膨らませている間は生成SEがループし、最後の指を離す・風へ切り替える・操作をキャンセルする・設定を開くと止まる。複数指で生成している場合は、生成中の玉がなくなるまで継続する。揺れる時と割れる時は、それぞれ別のSEが鳴る。

### 本書で補完した初期案

以下の数値、操作競合の解決方法、自動出現、設定UIは実装を具体化するための初期案。定数にまとめ、実機で調整できるようにする。

## 3. 対象環境・構成

- 主対象：iPhoneのSafari、AndroidのChrome。実装時点の安定版で確認する。
- PCのマウスでも同じ遊びを試せること。
- 縦持ちを基本とし、横持ち・画面サイズ変更にも追従する。
- サーバー処理、ログイン、データベース、外部APIは不要。
- 画像・フォント・音声の外部配信サービスに依存しない。

## 4. 画面

- 起動時とリセット時のシャボン玉は0個。7秒ごとに個数を確認し、ランダムに決めた補充目標1〜3個に足りなければ1個ずつ補充する。補充サイズは最大サイズの1/3〜最大サイズからランダムに決める。個数上限は10〜100個から設定し、初期値は20個。上限以上で追加すると、最も古い玉から雫付きで割って入れ替える。上限を下げた場合も次の追加時に適用する。開始画面は挟まない。
- 背景は鮮明なHDR画像を使い、設定から「公園」「夜明けの山」「室内」「夜景」の4種類を選べる。画像は同梱し、選択は端末に保存する。玉の輪郭が見分けられる明度差を確保する。
- 遊ぶ画面に説明文、点数、広告、リンクを配置しない。
- 右上の小さな設定アイコンを0.75秒長押しすると設定を開く。操作中は進捗を表示する。
- 設定では「シャボン玉の上限」「背景の選択」「リセット」を用意する。音の設定は設けず、常にオン・マスター音量100%とする。設定を開いている間は遊びを一時停止する。
- 設定はlocalStorageに保存し、保存できない環境でも遊びは継続する。
- UIは画面端のセーフエリアを考慮する。設定UIのタッチは遊びに伝播させない。
- シャボン玉のグラフィックはこだわる。

### 5.1 操作の優先順位

1. 設定UIへの入力。設定UIのアイコンを一定秒数押し続けることで、設定UIに切り替わる。
2. 指が開始点から一定pxを超えて移動した場合の「風」。
3. 空白を一定ms以上押し続けた場合の「生成」。
4. 玉の上で始まり、一定ms未満かつ一定12px以内で離した場合の「タップ」。

判定は現在の位置だけでなく、押してからの最大移動距離で行う。一度風になった入力は、指が元の場所に戻ってもタップや生成に戻らない。

## 7. 風・漂流

- なぞった方向と速さから風を計算する。右へなぞれば右、上へなぞれば上へ加速する。
- なぞる速度から周囲の空気の目標速度を求め、玉と空気の相対速度に応じて追従する。風がある間の追従率は4/慣性係数、風がない間の減速率は1.25/慣性係数とし、指数応答で時間刻みに依存しにくくする。大きい玉ほど動き出しと方向転換が遅く、風が止まった後も長く流れる。同じ風を受け続けた場合は大小とも同じ風速に近づく。
- 指の位置から遠い玉ほど影響を弱める。
- 速いスワイプでも影響が途切れないよう、イベント間の線分に対して判定する。
- 速度制限は風への追従・減速の計算後に適用し、大小で上限付近の速度が逆転することを防ぐ。
- 指を離した後も慣性で流れ、徐々に減速して通常の浮遊へ戻る。
- 生成直後はタップ時と同じように大きく揺らす（タップ回数は増やさない）。その後も元の位置を中心に上下左右へ約10pxゆっくり揺らし、一方向に上昇・移動し続けない。上下左右に流れるのは風を受けた場合だけとし、風が収まると減速してその場所にとどまる。
- 風で流れている間は、表示中心に装飾的な揺れを加算しない。風の開始時は表示中の位置を物理位置へ引き継いで位置飛びを防ぎ、停止後は約1.2秒かけて中心の揺れを戻す。風を受けている間は自動の伸縮・回転・膜表面の変形をその時点で保持し、輪郭の変化が初動速度に見えないようにする。風が止むと約0.25秒で自動変形へ戻す。明示的なタップの反応は優先する。
- 画面端では弱く跳ね返り、玉を画面内に保つ。玉同士は重なってよく、衝突や合体は実装しない。
- 生成中の玉は風の影響を受けず、放した後に受ける。
- 時間経過だけで自動破裂させない。

## 10. 見た目・音

- 膜の透過率は屈折率1.333のフレネル反射に従う。Schlick近似で一界面の反射率Rを求め、空気・膜・空気の二界面を考慮した反射率2R/(1+R)を使う。見やすさのため透過率に0.86の補正を掛け、正面は約83%透過とする。輪郭ほど反射が強くなる角度変化は維持する。
- 生成順に古い玉ほど奥、新しい玉ほど手前に描く。玉の枠を再利用した場合も生成順を守り、重なり部分のタップは手前の新しい玉に当てる。

- 玉は透明な内側、虹色の細い輪郭、白い弧状の反射で表現する。単なる塗りつぶしの丸にしない。
- 輪郭色を緩やかに変化させ、少し変形・揺動させる。強い点滅や画面全体のフラッシュは使わない。
- BGMはなし。

- 玉の内側では選択中のHDR背景がはっきり屈折し、球面への反射と虹色の膜で輪郭を見分けられるようにする。

- 破裂時は膜が32〜72個の雫に変わり、外へ飛び散って重力で落下しながら小さく消える。単に玉だけが消える見せ方にはしない。

- 膨張中・タップで揺れた時・破裂時のSEは、玉が大きいほど音量が大きくなる。個数上限による破裂にも適用する。マスター音量は100%固定で、複数同時の膨張音量には上限を設ける。過去の音量・ミュート設定は使わない。
- 風の影響半径は画面短辺の1/4とする。風が発生した線分から距離に比例して弱まり、半径の外には影響しない。縦長・横長を切り替えても短辺が同じなら同じ半径になる。
- 膜の厚さの変化による虹色の帯と渦状の干渉模様を、透明な内側にもゆっくり流す。

- 長押し中の成長は ease-out cubic（1−(1−t)^3）で、最初は急速に膨らみ、後半ほどゆっくりになる。最大到達時間は（最大半径−最小半径）/72秒。最大サイズは引き続き画面幅の約2/3。

- 玉の慣性係数はサイズに応じて1〜3。大きいほど同じ風での加速が小さく、減速も緩やかになる。風が止まると最終的には静止する。

- 設定ボタンには濃い青緑、設定パネルには不透明な明るい背景色を付け、背景写真に左右されず読めるようにする。
